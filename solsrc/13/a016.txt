=== 13.22.1
Use two arrays, a "sparse set":

- `A[1..n]`, indexed by value
- `B[1..n]`, holding the members densely
- a counter `count`, starting at 0

The invariant: $X\in S$ iff $1 \le A[X] \le count$ and $B[A[X]] = X$. So the arrays never need initialising.

```
MEMBER(X):   return (1 <= A[X] <= count) and (B[A[X]] = X)
FIND-ONE(S): if count = 0 then "empty" else return B[1]
ADD(X):      if not MEMBER(X) then
                 count := count + 1;  B[count] := X;  A[X] := count
DELETE(X):   if MEMBER(X) then
                 k := A[X];  Y := B[count];       { last element }
                 B[k] := Y;  A[Y] := k;           { move it into the hole }
                 count := count - 1
```

**Example:** with S = {7, 2, 9}, count = 3 and B = [7, 2, 9, …]. Then A[7] = 1, A[2] = 2 and A[9] = 3. Every operation is $O(1)$.
=== 13.22.2
1. **Reverse the queue's order onto the stack.** Delete each item from Q and push it onto S, $n$ times. The front item is now at the **bottom**, i.e. the order is reversed.
2. **Pop everything back into the queue.** Pop S and insert into Q, $n$ times. Q now holds the items in **reverse** order.
3. **Move to the stack again.** Delete from Q and push onto S, $n$ times. Q's reversed order puts the **original front item last**, so it's now on the **top** of S, with every other item in order.

That's $3n$ operations, i.e. $O(n)$. The only extra storage is one temporary variable.

=== 13.22.5
- **Pushes, $x$.** Every insert pushes once onto S1, which is $n$ pushes. Each element that is eventually deleted gets moved to S2, which is one more push. All $m$ deleted elements must be moved, and elements that are never deleted may be moved too, but at most $n$ in all. So $n + m \le x \le 2n$.
- **Pops, $y$.** Each deleted element is popped from S1 when moved and from S2 when deleted, which is $2m$ pops at least. Other elements may be moved, adding pops up to $n + m$. So $2m \le y \le n + m$.

**Option A**.
