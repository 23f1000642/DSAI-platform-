=== 1.52.1

=== 1.53.1
With a fixed pivot (first or last element), sorted input and reverse-sorted input are both worst cases. Each partition removes only the pivot. [1 2 3 4] has 4 elements and [5 4 3 2 1] has 5, so the 4-element input does less work:

$t_1 = \binom42 = 6$ comparisons, and $t_2 = \binom52 = 10$. So $t_1 < t_2$, **option C**.

=== 1.53.3
With the last element as pivot, the worst case is every partition being as lopsided as possible: the pivot is always the largest or smallest remaining element. An **already sorted** input does this, e.g. $1, 2, 3, \dots, n$. So does a reverse-sorted one, $n, n-1, \dots, 1$.

Each pass then removes only the pivot, giving $\binom n2 = \Theta(n^2)$ comparisons.
=== 1.53.4
With the first element as pivot:

- For **sorted** input, each pivot is the minimum, so the partition is (0, k−1).
- For **reverse-sorted** input, each pivot is the maximum, so the partition is (k−1, 0).

Either way the subproblem sizes are $n-1, n-2, \dots$, giving $\frac{n(n-1)}{2}$ comparisons in both cases. **$C_1 = C_2$**, **option C**.
=== 1.53.5
Randomisation makes the **expected** time $O(n\log n)$ for every input. But an unlucky sequence of pivot choices (always the min or max) is still possible, so the **worst case** is $O(n^2)$. **Option C**.
=== 1.53.6
Choosing the median as pivot takes $O(n)$ and splits the array exactly in half:
$$T(n) = 2T(n/2) + O(n) = \Theta(n\log n)$$

=== 1.53.7
