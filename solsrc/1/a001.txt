=== 1.0.2
A Boolean function of $n$ variables has $2^n$ possible inputs. In general you can't tell whether the function ever outputs 1 without checking the input combinations. In the worst case that's all $2^n$ of them. (This is the SAT problem, and no polynomial algorithm is known for it.)

So the order is **exponential**, **option D**.
=== 1.0.3
- **8-Queens:** place queens one at a time and undo a choice when it leads to a conflict. That is **backtracking** (iv).
- **Single-source shortest paths:** Dijkstra always picks the closest unfinalised vertex. That is the **greedy approach** (iii).

=== 1.1.1
Activity $i$ occupies the interval $[s_i, f_i)$. Two activities are compatible when their intervals don't overlap. Either $i$ starts after $j$ finishes ($s_i \ge f_j$), or $j$ starts after $i$ finishes ($s_j \ge f_i$).

Only one of these can hold at a time, so the condition is an **or**, **option C**.
=== 1.2.1
**Key fact:** in a DFS of an undirected graph, every non-tree edge is a **back edge**. It joins a vertex to one of its ancestors. So for the new edge $(u,v)$, one endpoint is an ancestor of the other, and the cycle is that endpoint's tree path plus the edge $(u,v)$.

We don't know which endpoint is the ancestor. So we climb from both endpoints **alternately**, one step each. One of them reaches the other after at most (cycle length) steps, which keeps the time proportional to the cycle length.

```
x := u; y := v;
while (x <> v) and (y <> u) do begin
   if x <> P[x] then x := P[x];   { climb from u }
   if y <> P[y] then y := P[y];   { climb from v }
end;
if x = v then begin             { v is an ancestor of u }
   w := u; write(w);
   while w <> v do begin w := P[w]; write(w) end;
end else begin                  { u is an ancestor of v }
   w := v; write(w);
   while w <> u do begin w := P[w]; write(w) end;
end;
write(' back to ', u, '/', v)   { the edge (u,v) closes the cycle }
```

Each climb takes at most $L$ steps, where $L$ is the cycle length, and printing also takes $L$ steps. So the total time is $O(L)$.
=== 1.2.2
A left shift by $K$ means the new $A[j]$ is the old $A[(j+K) \bmod n]$. The indices split into $\gcd(n,K)$ cycles $i \to i+K \to i+2K \dots$ (mod $n$), and we rotate each cycle using a single `temp`.

- **Inner loop:** start at $j=i$ and keep copying `A[j] := A[(j+K) mod n]`. The last position in the cycle is the one whose successor is $i$, i.e. $j = (n+i-K) \bmod n$. That position receives `temp`.
- **Outer loop:** `min` records the smallest index visited (other than the start). The first cycle (from 0) visits all multiples of $g=\gcd(n,K)$, so `min` becomes $g$. The cycles start at $i = 0,1,\dots,g-1$, so the loop runs while $i < min$.

The completed blanks, in order:

1. `while i < min do`
2. `while j <> (n+i-K) mod n do`
3. `A[j] := A[(j+K) mod n];`
4. `A[(n+i-K) mod n] := temp;`
5. `i := i+1;`

Every element is moved exactly once, so the algorithm is linear and uses no extra array.
=== 1.2.3
Scan from **right to left** and keep the maximum seen so far. Start with `max = -∞`. If $X[i] > max$, then $X[i]$ is a leader, and you set `max = X[i]`.

That's one pass with $O(1)$ work per element, i.e. linear time. A left-to-right pass can't decide whether an element is a leader without seeing everything to its right. So the answer is **B**.
=== 1.2.4
$a_i+\dots+a_j = b_i+\dots+b_j$ is the same as $\sum_{k=i}^{j}(a_k-b_k)=0$.

Let $d_k = a_k - b_k \in \{-1,0,1\}$, and define prefix sums $P_0=0$, $P_k = P_{k-1}+d_k$. The span $(i,j)$ works exactly when $P_j = P_{i-1}$. So we need the two equal prefix values that are farthest apart.

Every $P_k$ lies in $[-n, n]$. So keep an array of size $2n+1$ storing the first index at which each value appears. For each $k$, the candidate length is $k - \text{first}[P_k]$.

That takes one pass, plus an array of size $O(n)$: **$\Theta(n)$ time and space**, **option C**.
=== 1.2.5
If all $1+2+4+8+16 = 31$ coins weighed 10 gm, the total would be 310 gm.

The actual total is 323 gm. The extra 13 gm comes from the 11 gm coins, 1 gm extra each. So the number of coins taken from the 11 gm bags is 13.

Each bag contributes a distinct power of two, so the binary representation is unique: $13 = 1 + 4 + 8$. Those are the counts from bags 1, 3 and 4.

The product of the labels is $1\times3\times4 = \mathbf{12}$.
