=== 1.61.27
$c$ is the sorted merge of $a$ and $b$. Assume $a[i] \ge b[i]$.

**III: $c[2i] \le a[i]$.** The elements $a[0..i-1]$, $b[0..i]$ and $a[i]$ itself are all at most $a[i]$. That's $2i+2$ elements, so $a[i]$ sits at index $2i+1$ or later in $c$. Hence $c[2i] \le a[i]$. ✔

**II: $c[2i] \ge b[i]$.** The elements $b[i..n-1]$ and $a[i..n-1]$ are all at least $b[i]$, which is $2(n-i)$ elements. So at most $2i$ elements of $c$ are smaller than $b[i]$, which gives $c[2i] \ge b[i]$. ✔

**I and IV fail.** Take $a = [3, 4]$, $b = [1, 2]$ and $i = 1$. Then $a[1] = 4 \ge b[1] = 2$ and $c = [1, 2, 3, 4]$, so $c[2] = 3$.

- I would need $3 \ge 4$, which is false.
- IV would need $3 \le 2$, which is false.

**II and III**, **option C**.
=== 1.61.28
The official answer is **C, $\Theta(n\log n)$**, and it assumes radix sort with a **fixed base** $b$, such as binary or decimal:

- the largest key is $n^k$, so a key has $d = \log_b n^k = k\log_b n = \Theta(\log n)$ digits
- each digit pass is a counting sort costing $\Theta(n + b) = \Theta(n)$
- the total is $\Theta(d\cdot n) = \Theta(n\log n)$

(If you're allowed to choose the base as $b = n$, a key has only $k$ digits, and the time drops to $\Theta(kn) = \Theta(n)$. GATE's intended reading is the fixed-base one.) **Option C**.

=== 1.65.1
**How it works.** This is the **minimax** algorithm, written as a recursive depth-first search of the game tree.

- At a leaf, it returns the static payoff.
- At a MAX node (player 1 to move), it starts from −INF and takes the **maximum** over all children, each evaluated with mode MIN.
- At a MIN node, it starts from +INF and takes the **minimum**, evaluating children with mode MAX.

The active procedure calls always form the current root-to-node path. The value returned at the root is the best payoff player 1 can guarantee against optimal play by player 2. It examines **every** node, so it takes $O(b^d)$ time.

**Reducing the search: alpha–beta pruning.** Pass two bounds down the recursion:

- $\alpha$: the best value MAX can already guarantee
- $\beta$: the best value MIN can already guarantee

At a MAX node, stop looking at children once value ≥ β, because MIN will never let play reach here. At a MIN node, stop once value ≤ α. The result is identical to minimax. With good move ordering (best moves first), the number of nodes examined drops to about $O(b^{d/2})$, so you can search about twice as deep in the same time.

Other options: depth cut-offs with a heuristic evaluation function, and move ordering or iterative deepening.
