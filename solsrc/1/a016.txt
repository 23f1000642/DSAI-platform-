=== 1.32.26
The loops visit every pair $(i,j)$, **including** both $(i,j)$ and $(j,i)$. Each swap-through-Temp is done once for $(i,j)$ and undone for $(j,i)$, and adding then subtracting $C$ cancels out.

The matrix ends up unchanged: **$A$ itself**, **option A**.
=== 1.32.27
For each of the $n$ outer iterations:

- the first inner loop halves $j$, so $p = \log n$
- the second inner loop doubles $k$ up to $p$, so it adds $\log p = \log\log n$ to $q$

So $q \approx n\log\log n$, **option D**.

=== 1.32.30
The `n<0` branch never runs for positive $n$. The recursion is called **before** printing, and it keeps calling convert(n/2) until n reaches 0. Then convert(0) checks `0 < 0`, which is false, so it calls convert(0) again, forever.

Nothing is ever printed, and the program doesn't terminate (in practice it ends with a stack overflow). **Option D**.

=== 1.32.34
In each step, count the character from `a` up and the one from `b` down, and advance $j$ **once**:

- A: `count[a[j]]++`
- B: `count[b[j++]]--`

At the end, all counts are 0 exactly when the two strings are anagrams.

- Option C advances $j$ twice in one iteration.
- Option A never advances $j$, so it loops forever.
- Option B counts both strings up.

=== 1.32.35
$f$ walks through the binary digits of $n$ with weights 1, 2, 4, …: a 1 bit **adds** the weight $k$, and a 0 bit **subtracts** it.

$20 = 10100_2$. From the least significant bit, the bits are 0, 0, 1, 0, 1 with weights 1, 2, 4, 8, 16:
$$-1 - 2 + 4 - 8 + 16 = \mathbf{9}$$
**Option C**.
