=== 3.11.2
**Conflicts on X:** T2's r(X) comes before T3's w(X) and before T1's w(X). T3's w(X) comes before T1's w(X). T1's w(X) comes before T4's r(X). So the edges are T2→T3, T2→T1, T3→T1, T1→T4 and T3→T4.

**Conflicts on Y:** T2's w(Y) comes before T4's r(Y), giving T2→T4.

The graph is acyclic, with order T2, T3, T1, T4. So S is **conflict serialisable**.

**Recoverability:** T4 reads X (last written by T1) and Y (written by T2). Both T1 and T2 commit **before** T4 commits, and no other reads-from relationships exist. So S is **recoverable**.

**Option C**.

=== 3.11.4
Write T1 as $a_1a_2a_3a_4$ = r1(X) w1(X) r1(Y) w1(Y), and T2 as $b_1b_2b_3b_4$ = r2(Y) w2(Y) r2(Z) w2(Z).

The only item both transactions touch is **Y**. A schedule is conflict serialisable exactly when every Y-conflict points the same way.

**Case 1: equivalent to T1 → T2.** $w_1(Y) = a_4$ must come before $r_2(Y) = b_1$. So all of T1 comes first, which is the serial schedule: **1** way.

**Case 2: equivalent to T2 → T1.** $w_2(Y) = b_2$ must come before $r_1(Y) = a_3$. Count by $j$, the number of T1 operations placed before $b_2$ ($j = 0, 1, 2$):

- before $b_2$: $b_1$ plus $j$ a's, which can be arranged in $j+1$ ways
- after $b_2$: the remaining $4-j$ a's and $b_3, b_4$, giving $\binom{6-j}{2}$ ways

$$1\cdot\binom62 + 2\cdot\binom52 + 3\cdot\binom42 = 15 + 20 + 18 = 53$$

Total: $53 + 1 = \mathbf{54}$, out of 70 possible interleavings.
