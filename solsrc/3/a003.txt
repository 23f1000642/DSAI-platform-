=== 3.4.10
**(a)**

- **B-tree:** a key may sit in an internal node or in a leaf, so a successful search stops at different depths. **$X_1$ = Variable**. An unsuccessful search always goes down to a leaf. **$X_2$ = Constant**.
- **B+-tree:** every key lives in the leaves, and all leaves are at the same depth. **$X_3$ = Constant** and **$X_4$ = Constant**.

**(b)(i)** V joins R with itself on R1.B = R2.A. That gives pairs $(a, c)$ where $(a,b)$ and $(b,c)$ are both in R:

| A | B |
|---|---|
| 1 | 3 |
| 1 | 4 |
| 2 | 5 |

(1→2→3, 1→2→4, 2→4→5.)

**(b)(ii)** After inserting (2, 11) and (11, 6), the new two-step chains are:

| A | B | chain |
|---|---|---|
| 1 | 11 | 1→2→11 |
| 2 | 6 | 2→11→6 |
| 11 | 7 | 11→6→7 |
| 11 | 8 | 11→6→8 |

These four tuples are the additional rows in V.
=== 3.4.11
Let $n$ be the number of pointers per node. A node then holds $n-1$ keys of 8 bytes each:
$$4n + 8(n-1) \le 512 \Rightarrow 12n \le 520 \Rightarrow n \le 43.3$$
So the degree is $n = \mathbf{43}$, **option C**.
=== 3.4.12
In a 2-3-4 tree, a full node is split **before** descending into it (pre-emptive splitting).

- The root [L P U] is full (3 keys), so split it first. P moves up to become the new root, with children [L] and [U].
- G < P, so go to [L]. G < L, so go to the leaf [B H I], which is full. Split it: H moves up into [L], giving [H L], with children [B] and [I].
- Insert G into [B], giving [B G].

```
               [P]
          /          \
       [H L]          [U]
      /  |   \       /    \
  [B G] [I]  [N]  [Q T]  [V X Z]
```
**Option B**.
=== 3.4.13
An internal node with $p$ child pointers holds $p-1$ keys:
$$6p + 14(p-1) \le 512 \Rightarrow 20p \le 526 \Rightarrow p = 26$$
**Option C**.
=== 3.4.14
Disks transfer data in **blocks**. A B+-tree node is sized to fit one block, so it holds hundreds of keys, and the tree is very shallow. That means only a few block reads per search. A binary search tree would need about $\log_2 n$ separate reads. **Option D**.
=== 3.4.15
A leaf holds $n$ (value, record-pointer) pairs plus one block pointer to the next leaf:
$$n(9+7) + 6 \le 1024 \Rightarrow 16n \le 1018 \Rightarrow n = 63$$
**Option A**.
=== 3.4.16
Order 4 means a node holds at most 3 keys, and a split happens on the 4th. Count the splits in the worst case:

- The 1st split can happen at insertion 4. After that, each leaf has 2 keys, and each further leaf split needs 2 more insertions.
- Leaf splits at insertions 4, 6, 8, 10: **4 splits**.
- The leaf splits at 4, 6 and 8 give the root 3 keys, so the split at 10 pushes a 4th key into the root. The root splits: **1 more**.

The maximum is $4 + 1 = \mathbf{5}$, **option C**.
=== 3.4.17
A leaf holds at most 2 keys, and an internal node has at most 3 pointers (2 keys). Insert 10, 3, 6, 8, 4, 2, 1:

| insert | effect | leaf splits so far |
|---|---|---|
| 10, 3 | leaf [3 10] | 0 |
| 6 | [3 6 10] splits into [3] [6 10], root [6] | 1 |
| 8 | [6 8 10] splits into [6] [8 10], root [6 8] | 2 |
| 4 | [3 4] | 2 |
| 2 | [2 3 4] splits into [2] [3 4]. The root [3 6 8] also splits | 3 |
| 1 | [1 2] | 3 |

That's 3 leaf splits. The official key is **4 (option C)**, which matches the alternative split convention: on a split, the left leaf gets the extra key, $\lceil 3/2\rceil$. Then 1 overflows [1 2 3] instead.

Under that convention:

- 3 + 10 + 6 splits into [3 6] [10]
- 8 joins [8 10]
- 4 splits [3 4 6] into [3 4] [6]
- 2 splits [2 3 4] into [2 3] [4]
- 1 splits [1 2 3] into [1 2] [3]

That's **4** leaf splits, **option C**.
=== 3.4.18
A B+-tree with at most 5 keys in a node has order 6 (6 pointers). Non-root nodes must be at least half full: $\lceil 6/2\rceil = 3$ pointers, which is 2 keys.

The minimum is **2**, **option B**.
=== 3.4.19
Search for 7 and follow the leaf chain:

1. Read the root [9]. Since 7 < 9, go left.
2. Read [5]. Since 7 ≥ 5, go to the second child.
3. Read leaf [5 7]. It contains 7.
4. Follow the leaf link to [9 11]. Both keys are < 15.
5. Follow the link to [13 15]. 13 counts, and 15 stops the scan.

That's **5** nodes.
=== 3.4.20
A non-leaf node with $p$ block pointers holds $p-1$ keys:
$$8p + 12(p-1) \le 1024 \Rightarrow 20p \le 1036 \Rightarrow p = 51$$
The maximum number of keys is $p - 1 = \mathbf{50}$.
=== 3.4.21
A B+-tree is **balanced** because every leaf is at exactly the same depth. All root-to-leaf paths have the same length. **Option A**.
=== 3.4.22
With order $p$ (child pointers):
$$2p + 8(p-1) \le 512 \Rightarrow 10p \le 520 \Rightarrow p = \mathbf{52}$$
=== 3.4.23
In a B+-tree, **only the leaf nodes** point to the data records. Internal nodes hold keys and child pointers, used only for routing. So B is the statement that's NOT correct. **Option B**.
=== 3.4.24
Every node must be at least half full, **except the root**. The root may have as few as 2 children (or a single key when it's a leaf). **Option A**.
