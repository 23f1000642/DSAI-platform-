=== 3.20.17
In BCNF, the left side of every non-trivial FD is a superkey. So FDs cause **no redundancy**: no fact implied by an FD is ever stored twice. **Zero**, **option A**.
=== 3.20.18
The FDs are $M\to O$, $NO\to P$, $P\to L$ and $L\to MN$. The decomposition is $R_1(L,M,N,P)$ and $R_2(M,O)$.

**(a) Lossless? Yes.** The common attribute is $M$, and $M\to O$, so $M$ is a key of $R_2$.

**(b) Dependency-preserving? No.**

- In $R_2$: $M\to O$ holds.
- In $R_1$: $P\to L$ and $L\to MN$ hold, and so does $MN\to LP$ (since $MN^+$ = everything).
- **$NO\to P$** can't be derived. Using only the projected FDs, $NO^+$ stays $\{N, O\}$. So **$NO\to P$ is not preserved**.

**(c)** In $R_1$ the keys are L, P and MN, and every FD there has a key on the left side. In $R_2$, M is the key. Both relations are in **BCNF**.
=== 3.20.19
A 3NF decomposition can always be made dependency-preserving, but a BCNF one sometimes can't. That doesn't give a guaranteed test, though: a BCNF decomposition might happen to preserve dependencies too.

What always tells them apart is checking the **BCNF definition** on each decomposition. The one that passes is BCNF. (If both pass, either label is fine.) **Option C**.

=== 3.20.26
- A relation with two attributes is always in BCNF. True.
- If every key has one attribute, there can't be partial dependencies, so it's in 2NF. True.
- 3NF allows a **prime** attribute to depend transitively on a key. True.
- **BCNF does not** allow this, because every FD's left side must be a superkey. So D is false.
