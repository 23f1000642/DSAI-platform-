=== 3.34.1
**C: Inverted file organisation.**

An inverted file keeps, for each value of a secondary (non-key) attribute, the list of records that have that value. So queries on secondary keys go straight to the matching records, without scanning the file.
=== 3.34.2
- Number of data blocks: $\frac{1\text{ GB}}{1\text{ KB}} = 2^{20}$. (A blocking factor of 8 means records are 128 bytes.)
- Each index block can point to 32 blocks (fan-out 32). The top-level block is the master index.

| level | entries (blocks pointed to) | index blocks | size |
|---|---|---|---|
| 1 | $2^{20}$ | $2^{20}/32 = 2^{15}$ | 32 MB |
| 2 | $2^{15}$ | $2^{10}$ | 1 MB |
| 3 | $2^{10}$ | $2^{5} = 32$ | 32 KB |
| 4 (master) | 32 | 1 | 1 KB |

That's **4 levels** of indexing, and the master index is **1 block (1 KB)**.
=== 3.34.3
**Data area.** Each 512-byte block holds $512/64 = 8$ records. $16384/8 = $ **2048 data blocks**.

**Index area (sparse, one entry per data block).** Each entry is key + pointer $= 14 + 2 = 16$ bytes, so a block holds $512/16 = 32$ entries.

| level | blocks |
|---|---|
| 1 | 2048/32 = 64 |
| 2 | 64/32 = 2 |
| 3 | 1 |

The index takes 67 blocks in **3 levels**.

=== 3.34.10
**Order of the B+-tree.** With $p$ pointers per node, $8p + 12(p-1) \le 4096$, so $20p \le 4108$ and $p = 205$.

**Levels needed** for $10^6$ records:

- $205^2 = 42025 < 10^6$
- $205^3 \approx 8.6\times10^6 \ge 10^6$

So there are **3** index levels. One more access reads the record's own block.

The total is $3 + 1 = \mathbf{4}$ disk accesses.
