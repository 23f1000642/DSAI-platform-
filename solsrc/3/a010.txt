- **S1 is true.** With two attributes $\{A, B\}$, the only possible non-trivial FDs are $A\to B$ or $B\to A$. Either way the left side is a key, so the table is in BCNF, and hence also in 1NF, 2NF and 3NF.

**Old schema:** (VOLUME, NUMBER) → YEAR. That's a dependency on **part** of the primary key, i.e. a partial dependency, so the old schema is only in 1NF.

**New schemas:**

Both new schemas are in BCNF. The **weakest** normal form that the new design satisfies and the old one doesn't is **2NF**, **option B**.
=== 3.20.36
1. **Extraneous attribute:** in $VW\to X$, W is extraneous because $V\to W$. So it becomes $V\to X$.
2. **Split** $Y\to VX$ into $Y\to V$ and $Y\to X$.
3. **Redundant FD:** $Y\to X$ follows from $Y\to V\to X$, so drop it.

=== 3.20.37
**Schema II:** the keys are (rollno, courseid) and (email, courseid). email → rollno has a left side that isn't a superkey, so it **violates BCNF**. But rollno is **prime**, so 3NF holds.

The others:

- **III** has marks → grade, a transitive dependency on a non-prime attribute, so it isn't 3NF.
- **IV** has courseid → credit, a partial dependency, so it isn't 2NF.

**Option B**.
=== 3.20.38
**Is it lossless?** Y = (PR) and Z = (QRS) share R. Since R → P, R is a key of Y, so the decomposition is **lossless**.

**Is it dependency-preserving?** R → P lies in Y, and QR → S and S → Q both lie in Z. So it **preserves dependencies**.

**Is each schema in BCNF?** Z's keys are QR and RS. S → Q has a left side that **isn't a superkey** of Z, so Z is **not in BCNF**.

So I is false and II is true. **Option C**.
=== 3.20.39
3NF allows a non-trivial FD $X\to A$ with $X$ not a superkey, but **only when $A$ is prime**. BCNF forbids this. So a relation in 3NF but not BCNF must have such an FD. **Option A**.

B and C describe violations of 3NF and 2NF, respectively.
=== 3.20.40
Use the rule: if the common attributes determine one side, the join is lossless.
