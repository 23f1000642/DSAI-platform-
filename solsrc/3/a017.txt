=== 3.34.12
**Data file.** A block holds $\lfloor1024/100\rfloor = 10$ records, so there are $25000/10 = 2500$ data blocks.

**Index file.** It's sparse, with one entry (anchor key + block pointer) per data block. Each entry is $15 + 5 = 20$ bytes, so a block holds $\lfloor1024/20\rfloor = 51$ entries. That needs $\lceil 2500/51\rceil = 50$ index blocks.

Binary search on the index then takes $\lceil\log_2 50\rceil = \mathbf{6}$ block accesses. That's enough to identify the data block.
=== 3.34.13
A **scan** reads every record.

- **Sorted** and **heap** files store records packed in consecutive blocks, so a scan reads each block once. That's I/O efficient.
- An **unclustered** tree or hash index scan fetches records through the index, which can cost about one I/O per record. That's inefficient.

**A and B**.

=== 3.37.3
Block nested loop costs $b_{outer} + b_{outer}\times b_{inner}$. The product term is the same either way, so the cost is smallest when the **smaller** relation $r$ is the outer one. **Option A**.

- **T1 outer:** $2000\times20 + 80 = 40080$
